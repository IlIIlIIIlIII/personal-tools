# 화면 꺼짐 방지 요청 조회

`Scripts/install-display-power-background.ps1`을 관리자 권한으로 한 번 실행하면
**PersonalTools DisplayPower** 예약 작업이 로그인마다 최고 권한으로 실행됩니다.
화면 꺼짐 요청을 5초 간격으로 조회하고 앱과 위젯은 자동으로 결과를 표시합니다.
앱을 종료해도 조회는 유지되며, 다시 실행할 때 조회 시작이나 UAC 승인이 필요하지 않습니다.
스크립트와 결과는 관리자만 수정 가능한 `%ProgramData%/PersonalTools/DisplayPower`에 보관됩니다.
앱은 30초 이상 갱신되지 않은 결과를 오류로 표시하고, 조회가 복구되면 자동으로 다시 표시합니다.
예약 작업이 설치되지 않은 환경에서는 기존 메뉴의 **관리자 권한으로 조회 시작**을 사용합니다.

Win+W → 위젯 추가에서 **화면 꺼짐 방지**를 선택합니다. 기존 **Personal Tools HDR**과 별개의
위젯이며 요청 수·프로세스 이름·사유·마지막 확인 시간을 바로 표시합니다. 여러 항목은 **다음**으로
넘깁니다. 작음은 1개, 보통은 2개, 큼은 4개 요청을 한 페이지에 표시합니다.
기존 HDR 위젯은 모니터 조작만 표시합니다. 두 위젯은 같은 패키지로 설치하되 독립적으로
추가·배치·크기 변경할 수 있습니다. 긴 이름과 사유 및 전체 경로는 본 메뉴에서 확인합니다.

`powercfg /requests`의 DISPLAY 항목만 집계합니다. 프로세스 외에 서비스·드라이버 요청도
표시하며, SYSTEM·AWAYMODE 등 절전 관련 요청은 포함하지 않습니다. 요청이 없다는 것은
화면이 반드시 꺼진다는 의미가 아닙니다. 전원 설정, 사용자 입력, request override 등은 별도입니다.
지원하는 출력은 영어/한국어이며, 해석할 수 없는 출력은 없음으로 처리하지 않고 오류로 표시합니다.

권한 취소, 연결 종료, 시간 초과, 명령 실패 시 이전 결과를 지우고 확인 실패로 표시합니다.
자동 조회는 결과 복구를 계속 확인하며, 수동 조회는 본 메뉴의 조회 시작 버튼으로 재시도합니다.
프로세스 종료나 전원 설정 변경 기능은 없습니다.

## 구현과 검증

- 자동 조회는 보호된 결과 파일을 읽습니다. 아래 파이프 방식은 예약 작업 미설치 시의 수동 조회입니다.
- 일반 권한 앱은 현재 사용자만 접근 가능한 임의 이름의 파이프 서버를 생성합니다.
- `DisplayPowerProbe.ps1`만 숨겨진 관리자 PowerShell에서 실행합니다. 이 도구는 고정된
  Windows `powercfg.exe /requests`를 실행하고 결과만 전송하며, 파이프로 명령을 받지 않습니다.
- 앱은 접속한 프로세스 ID를 확인하고 메시지 크기와 응답 시간을 제한합니다.
- 조회 도구는 부모 프로세스 ID·시작 시간을 확인하며 파이프가 끊어지면 종료합니다.
- 배포 시 `.ps1` 파일은 앱 출력/게시 폴더에 함께 복사됩니다.
- `Tests/Hdr`에는 출력 해석, 오류/빈 결과 구분, 위젯 페이지, IPC 왕복 테스트가 있습니다.
  `--integration`은 실제 PowerShell 조회 및 연결 해제 시 종료를 검증합니다. 일반 권한으로
  실행한 통합 테스트에서는 Windows의 관리자 권한 필요 응답을 검증합니다.

실제 환경 확인: 앱에서 UAC 승인 → 동영상 재생 등 DISPLAY 요청을 발생시키는 프로그램 실행 →
본 메뉴와 위젯의 이름·사유 확인 → 프로그램 종료 후 요청 소멸 확인. UAC 취소/재시도,
트레이 유지, 앱 종료 후 보조 PowerShell 종료도 확인합니다.

`Tests/Hdr`의 `--live-power` 옵션은 설치된 앱에서 조회를 시작하고 승인한 뒤 실행합니다.
15초 동안 DISPLAY 요청을 유지하는 테스트 프로세스를 생성하여 실제 감지, 확인 시간 갱신,
종료 후 요청 제거를 검사합니다. 테스트 프로세스의 요청은 종료 시 해제됩니다.

## 2026-09-27 배포 검증

- WinUI 앱 게시 및 실행 확인. 기존 `PersonalToolsBridge.dll`을 함께 배포하여 오디오
  장치·필터·EQ 처리 상태가 정상임을 확인했습니다.
- 기존 UI는 `ui-backup-display-power-20260927-111048`에 보관했습니다.
- 위젯 버전을 1.0.2.0으로 올리고 개발용 등록을 완료했습니다. Windows 패키지 상태는 `Ok`이며,
  실제 등록 경로의 DLL과 빌드 결과의 SHA-256이 일치합니다.
- 같은 버전의 개발용 재등록이 이전 경로를 유지하는 문제를 발견했습니다. 설치 스크립트는
  이제 등록된 경로를 확인하여 이전 파일이 계속 사용되면 성공으로 보고하지 않습니다.
- 사용자 UAC 승인 후 설치된 앱에서 Chrome의 `Video Wake Lock` DISPLAY 요청을 확인했습니다.
- `--live-power`가 설치된 앱의 IPC를 통해 테스트 프로세스 감지, 시간 갱신, 종료 후 요청 제거를
  모두 검증했습니다. 관리자 권한은 조회 도구에만 적용되며 본 앱은 일반 권한으로 실행됩니다.
- 1.0.2.0의 위젯 표시·상세·HDR 복귀는 사용자가 직접 정상 동작을 확인했습니다.
- 이후 사용자 요청에 따라 1.0.3.0에서 화면 꺼짐 방지를 독립 위젯으로 분리했습니다.
  분리 후 테스트 23개, MSIX 패키징 검증 및 개발용 등록이 통과했습니다. 등록된 두 위젯 정의와
  전체 509개 위젯 파일의 해시 일치를 확인했습니다.
- 업데이트 후 위젯 추가 목록에 기존 HDR만 남는 현상이 발생했습니다. 설치된 매니페스트에는
  두 정의가 있었으나 실행 중인 보드가 새 목록을 반영하지 않았습니다. Windows Web Experience의
  `WidgetBoard`·`Widgets` 및 Widgets Platform Runtime의 `WidgetService`를 재시작한 뒤,
  사용자가 **화면 꺼짐 방지** 항목이 나타남을 확인했습니다. 위젯 설정이나 캐시 파일은 삭제하지 않았습니다.

### 업데이트 후 새 위젯이 목록에 없을 때

먼저 설치된 패키지 버전과 실제 등록 경로를 확인합니다. 최신 패키지에 두 위젯 정의가 있는데도
추가 목록에 기존 위젯만 보이면 위젯 보드와 위젯 서비스를 재시작한 뒤 Win+W → 위젯 추가를
다시 엽니다. 패키지 제거 또는 위젯 설정 초기화는 필요하지 않았습니다.

## 2026-09-28 자동 관리자 조회 적용

- 로그인 트리거·Highest 권한으로 예약 작업을 설치하고 현재 Running 상태를 확인했습니다.
- 보호 폴더 ACL은 SYSTEM·Administrators만 수정 가능하며 현재 사용자는 읽기만 가능합니다.
- 설치된 WinUI DLL과 게시 결과의 SHA-256 일치를 확인했습니다. 기존 UI는
  `build/display-power-auto-backup-20260928-232854`에 보관했습니다.
- 앱 재시작 후 메뉴 조작 없이 위젯과 같은 IPC에서 현재 요청을 확인했습니다.
- HDR 테스트 23개와 `--live-power`의 실제 요청 발생·확인 시간 갱신·종료 후 제거 검증이 통과했습니다.
- 위젯 보드의 실제 렌더링과 재로그인 후 예약 작업 실행은 이번 검증에 포함되지 않았습니다.
